# 数据库操作安全说明

## ⚠️ 重要提醒

**请在执行任何数据库脚本前，确保：**
1. 已备份当前数据库数据
2. 理解脚本的功能和影响范围
3. 在测试环境验证脚本无误后，再在生产环境执行

---

## 数据库脚本分类

### 1. 安全脚本（可以安全执行）

**初始化脚本（已优化为安全模式）：**
- `init_tenant.sql` - 初始化租户数据（使用INSERT IGNORE）
- `init_auth.sql` - 创建认证相关表（使用CREATE TABLE IF NOT EXISTS）
- `init_auth_data.sql` - 初始化认证数据（已优化，使用INSERT IGNORE）
- `init_role_menus.sql` - 初始化角色菜单关联（已优化，不会删除已有数据）

- `init_role_menus.sql` - 角色菜单关联（已优化）

### 2. 需谨慎执行的脚本

**Migration脚本（可能包含DELETE操作）：**
- `migration_20260412_keep_only_10_room_types_per_tenant.sql` - ⚠️ 会删除超过10个的房型
- 其他migration脚本 - 请仔细阅读脚本内容

**⚠️ 特别注意：**
- 执行前请务必备份数据库
- 理解脚本要删除什么数据
- 确认是否真的需要执行

## 数据保护措施

### 已实施的保护措施

1. **使用 INSERT IGNORE**
   - 避免重复插入数据
   - 不会覆盖已有的自定义数据

2. **使用 CREATE TABLE IF NOT EXISTS**
   - 不会删除或修改已存在的表

3. **删除操作已注释或优化**
   - `init_role_menus.sql` 中的 DELETE 已移除
   - 改为仅在无数据时才初始化
   - `init_auth_data.sql` 中的密码更新已注释

4. **添加执行结果提示**
   - 脚本执行后会显示当前数据统计
   - 帮助确认操作结果

## 如何安全执行脚本

### 推荐的执行顺序

1. **先备份数据库**
   ```bash
   mysqldump -u root -p CRS > CRS_backup_20260413.sql
   ```

2. **在测试环境验证**
   - 先在测试数据库执行
   - 检查执行结果是否符合预期

3. **阅读脚本内容**
   - 理解脚本要做什么
   - 注意是否有DELETE、TRUNCATE等操作

4. **按需执行**
   - 只执行你需要的脚本
   - 不要盲目执行所有脚本

## 常见问题

### Q: 我的用户数据被删除了怎么办？
A: 
1. 检查是否有备份
2. 如果没有备份，查看最近的migration脚本
3. 从备份恢复数据

### Q: 如何确认脚本不会删除我的数据？
A:
1. 仔细阅读脚本内容
2. 查找是否有DELETE、TRUNCATE、DROP等语句
3. 使用INSERT IGNORE的脚本是安全的

### Q: 我想重新初始化但保留用户数据怎么办？
A:
1. 先备份用户和角色数据
2. 执行其他初始化脚本
3. 从备份恢复用户数据
