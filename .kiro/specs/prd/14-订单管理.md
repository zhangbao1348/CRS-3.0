## 一、概述

### 1.1 业务背景

订单管理是 CRS 中央预订系统的核心模块，承接实时查询接口的预订流程，管理酒店全渠道预订订单的完整生命周期。订单来源包括：

1. **渠道直连订单**：通过开放 API（`/api/open/reservations`）由携程、飞猪、美团等渠道自动创建
2. **呼叫中心订单**：由 CRS 后台操作人员手动创建
3. **PMS 同步订单**：从酒店 PMS 系统同步的订单（后续扩展）

### 1.2 设计原则

1. **订单不可变原则**：订单创建后核心字段（价格、日期、房型等）不可直接修改，需通过"取消+重建"或"变更单"方式处理
2. **状态机驱动**：订单状态变更严格遵循状态机流转，每次变更记录操作历史
3. **库存联动**：订单创建/取消/完成自动联动库存扣减/释放
4. **渠道隔离**：渠道订单仅能查看和操作本渠道数据，CRS 后台可查看全渠道数据
5. **数据冗余**：订单关键信息（酒店名称、房型名称、价格计划名称等）在创建时快照存储，不依赖关联表实时查询

### 1.3 与实时查询接口的关系

```
接口1: 查询酒店列表  ──┐
接口2: 查询酒店详情与价格 ──┼── 前置查询（选酒店、选房型、选价格）
接口3: 可订检查  ────────┘
         │
         ▼
接口4: 创建订单 ──────── 订单管理模块入口
接口5: 支付订单 ──────── 订单支付流程
         │
         ▼
  CRS 订单管理（本模块）
  ├── 订单列表（后台查看/筛选/导出）
  ├── 订单详情（完整信息展示）
  ├── 订单操作（取消/完成/人工干预）
  └── 订单报表（统计分析）
```

## 三、订单状态机

### 3.1 预订状态（reservation_status）

```
                    ┌──────────────┐
                    │   pending    │  ← 呼叫中心创建待确认
                    └──────┬───────┘
                           │ 确认
                           ▼
                    ┌──────────────┐     取消     ┌──────────────┐
         ┌─────────│  confirmed   │──────────────│  cancelled   │
         │         └──────┬───────┘              └──────────────┘
         │                │
         │                │ 入住
         │                ▼
         │         ┌──────────────┐     离店     ┌──────────────┐
         │         │  checked_in  │──────────────│  checked_out │
         │         └──────┬───────┘              └──────────────┘
         │                │
         │                │ 未到
         │                ▼
         │         ┌──────────────┐
         │         │   no_show    │
         │         └──────────────┘
         │
         │  取消
         ▼
  ┌──────────────┐
  │  cancelled   │  ← confirmed/pending 状态可取消
  └──────────────┘
```

### 3.2 状态枚举定义

| 状态值 | 中文名 | 说明 | 可流转到 |
|--------|--------|------|---------|
| pending | 待确认 | 呼叫中心创建的订单待确认 | confirmed, cancelled |
| pending_payment | 待支付 | 全额预付订单待支付，等待支付完成 | confirmed, cancelled |
| confirmed | 已确认 | 订单已确认，等待入住 | checked_in, cancelled, no_show |
| checked_in | 已入住 | 客人已办理入住 | checked_out |
| checked_out | 已离店 | 客人已退房离店 | —（终态） |
| cancelled | 已取消 | 订单已取消 | —（终态） |
| no_show | 未到 | 客人未按时到店 | —（终态） |

### 3.3 支付状态（payment_status）

| 状态值 | 中文名 | 说明 |
|--------|--------|------|
| unpaid | 未支付 | 订单创建，等待支付 |
| paid | 已支付 | 支付成功 |
| partial_refunded | 部分退款 | 部分退款成功 |
| refunded | 已退款 | 全额退款成功 |

### 3.4 记录状态（status）

| 状态值 | 说明 |
|--------|------|
| active | 有效订单 |
| cancelled | 已取消 |
| completed | 已完成 |

## 四、用户故事与验收标准

### US-ORD-01：订单列表

**作为** 酒店前台/管理人员，**我希望** 在订单列表页查看所有渠道的预订订单，**以便** 全面掌握酒店预订情况。

**AC-ORD-01-1：** 列表展示订单号（渠道订单号/CRS订单号/PMS单号三行展示）、状态、渠道、预订时间、住宿日期、入住人、总房价
**AC-ORD-01-2：** 状态标签颜色：已确认=green、已取消=green、取消失败=red、已入住=blue、已离店=gray
**AC-ORD-01-3：** 人工干预订单在订单号旁显示红色"人工干预"Badge
**AC-ORD-01-4：** 支持按订单号、状态、渠道、入住人姓名筛选
**AC-ORD-01-5：** 支持分页，默认每页20条
**AC-ORD-01-6：** 点击"查看"跳转到订单详情页
**AC-ORD-01-7：** 支持导出订单列表为CSV

### US-ORD-02：订单详情

**作为** 酒店前台/管理人员，**我希望** 查看订单的完整详情信息，**以便** 了解预订全貌并处理客人需求。

**AC-ORD-02-1：** 顶部展示CRS订单号、渠道订单号、来源渠道、PMS单号、创建时间、状态
**AC-ORD-02-2：** 酒店及房间信息区展示：酒店名称、房型名称、入住日期~离店日期（N晚M间）
**AC-ORD-02-3：** 预订人信息表格：姓名、手机号、邮箱、会员等级、会员号
**AC-ORD-02-04：** 入住人信息表格：房间号、姓名、手机号、邮箱、会员等级、会员号、PMS订单号、PMS状态
**AC-ORD-02-05：** 档案信息表格：公司名称、公司税号、公司会员号、档案类型
**AC-ORD-02-06：** 订单备注：客人备注 + 门店备注
**AC-ORD-02-07：** 价格概览：订单原价（删除线）、订单金额（红色加粗）
**AC-ORD-02-08：** 每日价格卡片展示：日期、原价（删除线）、实际价格、早餐、特殊项；点击可弹出价格详情弹窗。弹窗包含费用、包价、税费三个 Tab 标签页，并根据当前点击日期的 `reservation_daily_price` 快照镜像动态进行数据对齐绑定：
  - **费用 Tab**：动态绑定显示该日的折扣前房费（`originalPrice`）和折扣后房费（`actualPrice`）。
  - **包价 Tab**：动态解析并展现该日固化的 `packages_json` 包价列表快照。展示每一项的包价名称、数量和包价类型。如果该日期无任何有效包价，则展示“无包价信息”。
  - **税费 Tab**：动态展示该日的增值税（`taxAmount`）和服务费（`serviceCharge`）。
**AC-ORD-02-09：** 促销信息表格：优惠名称、折扣、优惠金额、优惠券码、优惠承担方
**AC-ORD-02-10：** 支付信息：担保规则、支付状态、支付明细表格（支付方式/流水号/金额/时间/信用卡号/安全码/有效期；支付方式需由后端 DisplayMapper 根据支付代码，如 alipay/wechat_miniprogram，自动进行中文字样映射转换并在详情页展现）

## 六、业务规则

### 6.1 预订号生成规则

格式：`CRS` + `yyyyMMdd` + `6位序列号`

示例：`CRS20260501000001`

实现方式：使用数据库序列或 Redis 自增，保证唯一性。

### 6.2 库存联动规则

| 操作 | 库存影响 |
|------|---------|
| 创建订单 | 每日 available_rooms -= roomCount |
| 取消订单 | 每日 available_rooms += roomCount |
| 修改订单（增加房间数） | 差额扣减 available_rooms |
| 修改订单（减少房间数） | 差额释放 available_rooms |
| No Show | 不释放库存（已扣减不退回） |

### 6.3 取消政策执行规则

| 取消政策类型 | 规则 |
|-------------|------|
| free | 任意时间免费取消，全额退款 |
| limited | 入住前N天HH:mm前免费取消，之后扣首晚/全额房费 |
| non_refundable | 不可取消，取消扣全额房费 |

### 6.4 渠道通知规则

| 订单事件 | 通知渠道 | 通知方式 |
|---------|---------|---------|
| 订单创建 | 对应渠道 | 回调通知 |
| 订单取消 | 对应渠道 | 回调通知 |
| 客人入住 | 对应渠道 | 回调通知 |
| 客人离店 | 对应渠道 | 回调通知 |
| No Show | 对应渠道 | 回调通知 |

### 6.5 数据隔离规则

1. 渠道通过开放API仅能查看/操作本渠道创建的订单
2. CRS后台可查看/操作所有渠道的订单
3. 所有数据按 tenant_id 隔离
