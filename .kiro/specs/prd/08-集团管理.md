# 集团管理

集团管理是 CRS 系统的核心管理模块，负责集团层面的基础数据维护和策略配置。集团管理员通过此模块统一管理旗下酒店、房型、房价码、市场码、渠道码等基础数据，并将配置下发到各酒店执行。

集团管理包含以下菜单：酒店管理、集团房型管理、集团房价码管理、市场码管理、房价大类管理、房型大类管理、渠道码管理、来源码管理、税和服务费设置、包价设置、集团担保政策管理、集团取消政策管理、集团设施管理、档案管理。以上为目前已规划的功能。

**全局代码字段规则：** 本模块中所有"代码"类字段（酒店代码、房型代码、房价代码、市场码代码、来源码代码、渠道码代码、房价大类代码、房型大类代码、税费项编码、包价代码、担保政策代码、取消政策代码、设施代码、档案 ID 等）统一遵循以下输入规则：
- 只允许输入英文字母、数字和下划线（_）
- 不允许中文、空格、特殊字符
- 正则表达式：`^[A-Za-z0-9_]+$`

## 1. 酒店管理

### 1.1 酒店列表 ✅ 已实现

进入集团酒店管理后，点击酒店管理菜单进入酒店列表页面。页面顶部为查询区域，支持按酒店名称（模糊匹配）、酒店编码、所在城市、状态进行筛选。查询结果以列表形式展示，包括酒店名称、酒店编码、省份、城市、地址、创建时间、状态等信息。

每条酒店记录提供查看、编辑和删除操作。查看操作弹出酒店基本信息的只读视图；编辑操作跳转到编辑页面；删除操作需要二次确认，执行软删除（不影响已下发的房型和房价码数据）。

列表右上方有"新增酒店"按钮，点击后跳转到新增酒店页面。

所有酒店数据按当前选择的租户进行隔离，不同租户只能看到自己的酒店。

### 1.2 新增/编辑酒店 ✅ 已实现

新增和编辑酒店包含 4 个 Tab 页：基本信息、酒店设施、酒店图片、酒店管控。

#### Tab 1：基本信息

基本信息包括以下字段：

- **酒店代码**（必填，最大50字符）：用户输入，同一租户下不可重复，保存后不可修改。*为空提示："请输入酒店代码"；格式不符提示："酒店代码仅允许输入英文字母、数字和下划线，请重新输入"；代码重复提示："该酒店代码已被占用，请使用其他代码"*
- **归属集团**（只读）：自动显示当前登录用户所属的租户名称，数据来源：TenantContext
- **酒店中文名称**（必填，最大100字符）：用户输入。*为空提示："请输入酒店中文名称"*
- **酒店英文名称**（选填，最大100字符）：用户输入
- **酒店星级**（必填）：下拉选择，选项：一级/二级/三级/四级/五级（静态枚举）。*未选择提示："请选择酒店星级"*
- **所在省份**（必填，最大50字符）：下拉选择，选项来源：静态枚举（江苏省/浙江省/上海市/北京市/广东省等）。选择省份后，城市下拉框联动更新。*未选择提示："请选择酒店所在省份"*
- **所在城市**（必填，最大50字符）：下拉选择，选项来源：根据所选省份动态过滤（目前为静态枚举）。*未选择提示："请选择酒店所在城市"*
- **酒店所在区域**（选填，最大50字符）：下拉选择，选项来源：系统设置 > 字典管理中 `REGION` 字典类型下的启用字典项；页面显示字典项名称，保存时存储字典项编码
- **详细地址**（必填，最大200字符）：用户输入。*为空提示："请输入详细地址"*
- **酒店经度**（必填）：用户输入，数值类型。*为空提示："请输入酒店经度"；超出范围提示："请输入正确的经度数值（范围 -180 至 180）"*
- **酒店纬度**（必填）：用户输入，数值类型。*为空提示："请输入酒店纬度"；超出范围提示："请输入正确的纬度数值（范围 -90 至 90）"*
- **联系电话**（必填，最大20字符）：用户输入。*为空提示："请输入联系电话"；格式错误（仅允许数字和横杠）提示："联系电话格式不正确，仅允许数字和横杠，请重新输入"*
- **邮箱**（必填，最大100字符）：用户输入。*为空提示："请输入邮箱地址"；格式错误提示："请输入合法的邮箱地址，例如 hotel@crs.com"*
- **总房间数**（必填）：数字输入，最小值1。*为空提示："请输入总房间数"；非正整数提示："总房间数必须为大于 0 的整数"*
- **酒店最低价格（含税）**（选填）：数字输入，精度 2 位小数，最小值 0。用于维护酒店级价格下限，保存后在新增/编辑页均需正确回显
- **应用集团税率**（选填）：多选 Select，选项来源于“集团管理 > 税率设置”中已启用的集团税率列表。选择并保存后自动应用于该酒店
- **酒店简介**（选填）：富文本编辑器（wangEditor），无长度限制

保存后自动切换到下一个 Tab。

**酒店所在区域业务规则：**
- 新增/编辑酒店时，`酒店所在区域` 使用字典管理中的 `REGION` 字典类型作为唯一数据源，仅展示 `status=active` 的字典项。
- 酒店保存时落库存储 `REGION` 子项的 `itemCode`，以保证后续字典名称调整时历史酒店数据仍可稳定回显。
- `酒店所在区域` 与省份、城市并存，当前版本不做省市与区域的联动校验。

**应用集团税率业务规则：**
- 酒店绑定了哪些集团税率，在计算房价时将以此进行计算。
- **自动触发房价码不含税价重算**：当集团管理员保存/更新酒店信息时，系统自动汇总所选集团税率的税率百分比（如增值税 6% + 服务费 10% = 16%）。系统随后自动重新计算该酒店名下所有已存房价记录 (`hotel_prices`) 的不含税价格：
  `price_without_tax = price_with_tax / (1 + 税率总和)`，计算结果四舍五入保留两位小数并持久化。

**酒店最低价格（含税）业务规则：**
- 当集团管理员保存酒店基础信息时，如果该酒店下任一 `hotel_prices` 有效价格记录的 `price_with_tax` 低于酒店最低价格（含税），系统需自动将该记录抬升为酒店最低价格（含税）。
- 上述规则仅作用于 `status=active` 的有效价格记录；`inactive`/已删除价格不参与自动抬升。
- 后续酒店端保存单日价格、批量保存价格、以及系统自动计算衍生房价码价格时，任一日期的含税价格若低于酒店最低价格（含税），都必须按酒店最低价格（含税）落库。

#### Tab 2：酒店设施

酒店设施按类别分组展示，每个类别下有多个设施选项供勾选。类别包括：交通服务、餐饮服务、清洁服务、休闲娱乐、商务服务、前台服务、通用设施。每个类别下的具体设施项参见集团设施管理中的标准设施列表。

#### Tab 3：酒店图片

支持上传酒店店图、外观图片、餐厅图片、大堂图片，每种类型限 1 张。支持点击上传和拖拽上传，支持预览和删除。

#### Tab 4：酒店管控

酒店管控分为房型分配和房价码分配两个区域。

**房型分配：** 展示集团所有房型列表，每个房型有"是否分配到酒店"和"允许酒店修改房型信息"两个开关。支持按房型大类分组显示，支持全选操作。取消分配时自动关闭"允许修改"开关。 ✅ 已实现

**房价码分配：** 展示集团所有房价码列表，每个房价码有"是否分配到酒店"以及 5 个权限开关（基础信息可修改、价格信息可修改、预订限制可修改、担保/取消规则可修改、促销优惠可修改）。支持按房价大类筛选，筛选下拉显示格式为"房价大类名称（房价数量）"。支持全选操作。取消分配时自动关闭所有权限开关。 ✅ 已实现

**多入口分配的数据一致性说明：**

酒店管控中的房型分配/房价码分配，与集团房型管理 Tab 2（房型分配）、集团房价码管理 Tab 2（房价码分配）操作的是同一份底层数据。两个入口只是视角不同，为了方便不同场景下的操作：
- **酒店管控视角**（以酒店为中心）：编辑某个酒店时，一次性查看和管理该酒店被分配了哪些房型和房价码
- **房型/房价码分配视角**（以房型或房价码为中心）：编辑某个房型或房价码时，一次性查看和管理它被分配到了哪些酒店

在任一入口修改分配状态并保存后，另一入口打开时应实时反映最新的分配结果，无需额外同步操作。

**分配业务规则：**

#### 用户故事：房价码下发到酒店

**作为**集团管理员，**我希望**将集团房价码下发到指定酒店，**以便**酒店能够使用统一的定价策略进行销售。

**下发流程：**

1. 集团管理员在酒店管控页面或集团房价码分配页面，勾选需要下发的酒店
2. 系统在该酒店创建一条与集团房价码相同的价格计划记录，状态为有效
3. 下发时，集团房型信息也需要同步下发到酒店。酒店应有独立的表结构存储这些房价码数据，以便后续根据权限进行修改
4. 下发完成后，酒店端的价格计划列表中应能看到已下发的房价码
5. 如果下发的是衍生房价码（一级/二级衍生码）：
   - **前提**：必须确保其父级房价码已经下发到目标酒店。若父级未下发，该衍生码下发失败，系统阻断并提示。
   - **价格生成**：若父级已下发，系统自动查找父级在该酒店已有的有效价格数据，按衍生码配置计算并写入。若父级在该酒店暂无价格数据，则衍生码依然可以成功下发，只是不触发价格生成。

**验收标准：**
- 下发后，酒店价格计划列表显示新增的房价码记录
- 房价码的所有属性（名称、类别、市场码、来源码、担保规则、取消规则等）完整复制到酒店
- 同一房价码不可重复下发到同一酒店
- 衍生房价码下发后，如果父级有价格数据，酒店价格表中自动生成对应的衍生价格

#### 用户故事：房价码回收

**作为**集团管理员，**我希望**回收已下发到酒店的房价码，**以便**该酒店不再使用此定价策略。

**回收流程：**

1. 集团管理员取消勾选某酒店的"是否分配到酒店"开关
2. 系统将该酒店对应的价格计划记录置为失效状态（软删除）
3. 回收时不更改酒店已保存的房本或房源信息，仅改变状态
4. 酒店端的价格计划列表中不再显示该房价码（或显示为已失效）

**验收标准：**
- 回收后，酒店价格计划列表不再显示该房价码
- 酒店已有的历史订单数据不受影响
- 预订中（未入住）的订单不受影响，这些订单数据已快照
- 回收操作不物理删除任何数据

#### 用户故事：房价码再次下发

**作为**集团管理员，**我希望**将之前回收的房价码重新下发到酒店，**以便**恢复该酒店的定价策略。

**再次下发流程：**

1. 集团管理员重新勾选某酒店的"是否分配到酒店"开关
2. 系统检测到该酒店之前已有该房价码记录（失效状态）
3. 系统对比集团当前房价码信息与酒店已保存的信息，如果存在差异，弹窗提示哪些字段不同，由管理员确认是否覆盖更新
4. 确认后，系统更新酒店的价格计划记录为集团最新信息，并将状态恢复为有效
5. 同时需提醒相关修改用户或下发人，告知房价码已重新下发 ❌ 未实现

**验收标准：**
- 再次下发时，系统能识别出之前已回收的记录
- 差异对比弹窗清晰展示哪些字段发生了变化 ✅ 已实现
- 确认后酒店数据更新为集团最新版本

#### 用户故事：集团修改房价码后同步到酒店

**作为**集团管理员，**我希望**修改集团房价码信息后，系统能提示我是否同步到已下发的酒店，**以便**保持集团与酒店的数据一致性。

**同步流程：**

3. 如果存在差异，弹窗提示用户是否同步至对应酒店，并允许选择同步范围（全部酒店/部分酒店）
4. 用户确认后，系统批量更新选中酒店的价格计划记录
5. 如果酒店端已对该房价码做过自定义修改（在权限允许范围内），需特别提示"酒店已修改，是否覆盖" ❌ 未实现

**验收标准：**
- 修改保存后弹出同步确认弹窗 ✅ 已实现
- 弹窗展示受影响的酒店列表和差异字段 ✅ 已实现
- 支持选择性同步（全部/部分酒店） ✅ 已实现
- 酒店已自定义修改的字段有特殊提示 ❌ 未实现

#### 用户故事：酒店端查看和修改已分配的房价码

**作为**酒店管理员，**我希望**查看集团下发给我的房价码，并在权限范围内进行修改，**以便**根据本酒店实际情况调整定价策略。

**查看和修改规则：**

   - 预订限制可修改：会员等级要求、提前预订天数等
   - 担保/取消规则可修改：担保规则、取消规则
   - 促销优惠可修改：优惠券规则、促销规则、积分兑换
3. 权限未开放的字段显示为只读状态，需提醒操作人"此字段由集团管控，如需修改请联系集团管理员"

**验收标准：**
- 酒店端能正确显示已分配的房价码列表
- 权限开放的字段可编辑，未开放的字段只读
- 只读字段有明确的提示信息 ✅ 已实现

#### 用户故事：房型下发与房价码联动

**作为**集团管理员，**我希望**房价码下发到酒店时，关联的集团房型信息也同步下发，**以便**酒店能完整使用该房价码。

## 2. 集团房型管理

### 2.1 集团房型列表 ✅ 已实现

**作为**集团管理员，**我希望**查看和管理集团下所有标准房型模板，**以便**统一规范各酒店的房型体系。

进入集团房型管理后，页面展示当前租户下所有集团房型列表。顶部查询区域支持按房型名称（模糊匹配）、房型代码（精准匹配）、房型大类（下拉选择，数据来源：房型大类管理）、状态（启用/停用）进行筛选。

列表展示以下信息：房型代码、房型名称、所属房型大类名称、最大入住人数、排序序号、状态（启用显示绿色、停用显示红色）。

每条记录支持以下操作：
- **编辑**：跳转到编辑页面，回填已有数据
- **启用/停用**：切换房型状态（注：集团房型原则上不允许物理删除，如需废弃请设为停用状态）

列表右上方有"新增集团房型"按钮。

**房型停用对房价码的影响：** 停用集团房型时，如果该房型已被房价码选为适用房型，需要提示"该房型已被 X 个房价码引用"。停用的房型仍然显示在房价码的适用房型矩阵中，但标记为停用状态。

**房价码类型与衍生层级规则：**

| 类型 | 衍生层级 | 父级可选范围 | 说明 |
|------|---------|-------------|------|
| 基础房价码 | basic | 无（不需要父级） | 价格体系的根节点，直接定义基础价格 |
| 一级衍生码 | level1 | 仅可选择基础房价码 | 基于基础房价码派生，通过折扣/加价生成 |
| 二级衍生码 | level2 | 仅可选择一级衍生码 | 基于一级衍生码再次派生 |

**衍生码下发时的衍生链联动：** 下发衍生房价码时，系统需要检查其父级和祖父级房价码是否已经下发到目标酒店。如果父级/祖父级房价码未下发，且不在本次批量下发的范围内，则该衍生码下发失败，提示"XXX 房价码下发失败，需要先下发父级房价码（XX）"。

**集团房价码停用的级联影响：** 集团房价码设置为无效时，已经下发到酒店的该房价码全部置为无效。停用前需提示"已下发到 X 家酒店的房价码都会变更为无效，是否继续？"

**房价码下发与酒店端的一致性检查：**

系统在以下两个时机执行集团房价码与酒店端房价码的一致性对比：

1. **保存房价码时**：集团管理员修改房价码信息并保存后，系统检测该房价码是否已下发到酒店。如果已下发，对比集团最新信息与各酒店端已保存的信息，发现差异时弹窗提示是否同步到已下发的酒店（详见"集团修改房价码后同步到酒店"用户故事）。

2. **房价码再次分配时**：集团管理员将之前回收的房价码重新分配到酒店时，系统对比集团当前房价码信息与酒店端之前保存的信息，发现差异时弹窗提示哪些字段不同，由管理员确认是否覆盖更新（详见"房价码再次下发"用户故事）。

酒店端在权限范围内修改房价码后，酒店端的数据可能与集团不一致，这属于正常情况。一致性检查仅在上述两个时机由集团侧主动触发，不做实时自动同步。

- **取消政策代码**（必填）：用户输入，编辑时不可修改。*为空提示："请输入取消政策代码"；格式不符提示："取消政策代码仅允许输入英文字母、数字和下划线"；代码重复提示："该取消政策代码已存在"*
- **取消类型**（必填）：下拉选择，固定选项：免费取消 / 限时扣费 / 不可取消。*未选择提示："请选择取消类型"*
- **描述**（选填）：多行文本输入
- **状态**（必填，默认启用）：下拉选择，启用/停用。*未选择提示："请选择政策状态"*

[条件] 取消类型=限时扣费时，额外显示规则配置（以自然语言拼接的行内表单）：

> 入住前 [X] 天，[HH:mm] 前免费取消，之后扣 [首晚/全额房费]

具体字段：
- **提前天数**（必填）：数字输入，最小值 1。*为空或小于1的非正整数提示："提前天数必须是大于 0 的整数，请重新输入"*
- **截止时间**（必填）：时间选择器，格式 HH:mm（注：该时间及所有的前台业务时间限制，均以酒店所在地当地时间 Hotel Local Time 为准）。*为空提示："请选择截止时间"；格式错误提示："请输入正确的 24 小时制时间，例如 18:00"*
- **扣费类型**（必填）：下拉选择，固定选项：首晚 / 全额房费。*未选择提示："请选择扣费类型"*

切换取消类型为非限时扣费时，以上三个字段隐藏并清空值。

## 13. 集团设施管理 ✅ 已实现

集团设施管理以列表+弹窗形式管理标准设施。设施分为两种适用范围：酒店设施（用于酒店整体的设施配置）和房型设施（用于具体房型的设施配置）。

页面顶部有搜索区域，支持按以下条件筛选（前端过滤）：
- 适用范围（下拉选择，酒店设施/房型设施，可清空）
- 设施分类（下拉选择，选项根据适用范围联动，不选适用范围时显示所有分类，可清空）
- 设施名称（模糊匹配）
- 设施代码（模糊匹配）

列表展示以下信息：

| 列 | 说明 |
|----|------|
| 设施ID | 系统自增 ID |
| 设施分类 | 交通服务/餐饮服务/清洁服务 |
| 设施名称 | 设施显示名称 |
| 设施代码 | 唯一标识 |
| 适用范围 | 酒店设施 / 房型设施 |
| 设施描述 | 设施说明 |
| 状态 | 可用（绿色）/ 不可用（黄色） |
| 操作 | 编辑 |

列表右上方有"新增设施"按钮，点击后弹出模态框。

新增/编辑设施通过弹窗表单进行，包含以下字段（从上到下排列）：

- **适用范围**（必填，默认"酒店设施"）：下拉选择，酒店设施 / 房型设施。选择后设施分类下拉联动更新为对应的分类选项。*未选择提示："请选择适用范围"*
- **设施分类**（必填）：下拉选择，选项根据适用范围联动。*未选择提示："请选择设施分类"*：
  - 酒店设施：交通服务 / 餐饮服务 / 清洁服务 / 休闲娱乐 / 商务服务 / 前台服务
  - 房型设施：清洁服务 / 网络与通讯 / 客房布局和家具 / 洗浴用品 / 食品饮品 / 卫浴设施 / 媒体科技 / 客房设施 / 室外景观 / 便利设施
  - 切换适用范围时，设施分类自动清空，需要重新选择
- **设施名称**（必填）：用户输入。*为空提示："请输入设施名称"*
- **设施代码**（必填）：用户输入，编辑时不可修改。*为空提示："请输入设施代码"；格式不符提示："设施代码仅允许输入英文字母、数字和下划线"；代码重复提示："该设施代码已存在"*
- **设施描述**（选填）：多行文本输入
- **状态**（选填）：下拉选择，可用/不可用

*注：若必填项校验失败，保存时输入框下方应统一高亮呈现红色，并显示行内错误提示，同时阻止弹窗关闭。*

**适用范围说明：**
- 酒店管理页面的"酒店设施"Tab 仅查询适用范围为"酒店设施"的设施列表
- 房型管理页面的设施配置仅查询适用范围为"房型设施"的设施列表
- 集团设施管理列表展示所有设施（不区分范围）

## 14. 档案管理 ✅ 已实现

档案管理用于维护公司和旅行社档案信息，并为档案分配房价码。

### 14.1 档案列表

页面顶部为查询区域，支持按以下条件筛选：

- 档案 ID（模糊匹配）
- 档案名称（模糊匹配）
- 档案类型（下拉选择）
- 档案等级（下拉选择）
- 状态（下拉选择，启用/停用）

列表展示以下信息：

| 列 | 说明 |
|----|------|
| 档案 ID | 唯一标识 |
| 档案名称 | 档案显示名称 |
| 档案类型 | 公司（蓝色标签）/ 旅行社（绿色标签） |
| 档案等级 | 银卡/金卡/铂金卡/黑卡，不同等级不同颜色标签 |
| 档案联系人 | 联系人姓名 |
| 档案联系地址 | 联系地址 |
| 状态 | 启用/停用，点击状态标签可切换（需二次确认） |
| 操作 | 编辑 |

列表右上方有"新增档案"按钮。

### 14.2 新增/编辑档案

新增/编辑档案页面分为两个区域：基本信息和分配房价码。

**基本信息：**

- **档案 ID**（必填）：用户输入。*为空提示："请输入档案 ID"；格式不符提示："档案 ID 仅允许输入英文字母、数字和下划线"；代码重复提示："该档案 ID 已存在"*
- **档案名称**（必填）：用户输入。*为空提示："请输入档案名称"*
- **档案类型**（必填）：下拉选择，固定选项：公司 / 旅行社。*未选择提示："请选择档案类型"*
- **档案等级**（选填）：下拉选择，固定选项：银卡 / 金卡 / 铂金卡 / 黑卡
- **档案联系人**（选填）：用户输入
- **档案联系地址**（选填）：多行文本输入

**分配房价码：**

以表格形式管理档案关联的房价码，支持添加多行。每行包含：

- **酒店**（选填）：下拉选择，选择关联的酒店
- **房价码**（选填）：多选下拉，选择该酒店下关联的房价码
- **操作**：删除该行

表格上方有"添加"按钮，点击新增一行空白记录。

注：当前档案数据存储在 localStorage 中，未对接后端 API。
