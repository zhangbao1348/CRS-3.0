# 全系统链路追踪与 AI 诊断 (System-Wide Trace & AI Diagnostics)

全系统链路追踪与 AI 诊断底座负责对 CRS 系统内部的外部接口（Open API）、管理后台接口（Internal API）、异步定时任务（Scheduled Job）以及前端发生的 JavaScript 报错执行全生命周期的时序追踪。

通过“决策审计追踪 (Decision Audit Trail)”收集业务执行各阶段的“决策快照 (DecisionSnapshot)”，将临时计算和校验变量（如底标价覆盖、税率拆分、库存扣减、事务锁抢占等）结构化归档，为后续引入 AI 一键自动诊断提供标准的数据载体。

---

## 1. 业务目标与价值

在传统的 CRS 系统中，存在两类棘手的排查场景：
1. **系统性报错或偶发网络异常**：需要人工登录服务器拉取大量乱序日志，并逐行定位代码，排查时效低。
2. **“非报错类”业务争议（如价格/库存不符预期）**：订单创建成功，但客人对账时发现价格与设置的房价码不一致，或是渠道端提示无法预订。此类临时计算的中间状态通常不写入常规数据库表，人工复盘极度困难。

**全系统链路追踪旨在实现：**
* **TraceId 贯穿全链路**：一次用户操作（或一次定时调度）在前端、网关、逻辑层及事务层产生的动作，均使用相同的唯一 ID 串联。
* **业务白盒化（决策审计）**：对价格计算、税金拆分、配额校验的过程执行实时快照，确保“过程可追溯，结果可解释”。
* **AI-Ready 预诊断**：故障发生后，系统将出错代码行、异常堆栈、计算快照和参考 PRD 文档一键打包，使大模型可以直接进行故障分析并给出精确修复建议。

## 2. 术语与规格定义

### 2.1 链路标识 (Trace ID)
* **唯一标识**：全局唯一的 32 位无连字符十六进制字符串（由前端 Axios 请求拦截器动态生成，并在请求头 `X-Trace-Id` 中向后传递；如果为开放 API，则由网关过滤器生成）。
* **线程传播**：后端基于 `ThreadLocal` 与 SLF4J MDC（Mapped Diagnostic Context）保存 traceId，自动在标准应用日志输出中打印。
* **异步传递**：遇到异步线程池或调度器（如超时清理任务）时，必须通过上下文复制将 traceId 复制给子线程，任务结束时执行 `TraceContext.clear()` 释放内存。

### 2.2 决策快照 (DecisionSnapshot)
* **定义**：在核心服务层执行复杂规则判定时，捕获并收集到的参数状态的结构化 JSON 变量。
* **保存粒度**：每次请求生成一个合并后的 `decisionSnapshot`，以 JSON 字符串形式持久化在 `SystemTraceLog` 表中。

## 3. 全链路决策审计打点规范

在执行以下业务逻辑时，必须通过 `TraceContext.recordDecision(key, value)` 写入快照：

### 3.1 订单创建价格链 (OpenReservationController.createReservation)
在订单预订生成流程中，必须留存以下价格链决策点：
* **`dbOriginalPrices`**：从数据库中查出的所有原始房价列表（包含 `priceDate` 日期、`priceWithTax` 含税价、`priceWithoutTax` 不含税价、及 `isEffective` 有效状态）。
* **`hotelMinimumPrice`**：当前酒店配置的保底最低价限制。
* **`dbPriceMapAfterMinPrice`**：应用保底最低价覆盖后，计算出的每日价格 Map（键为日期，值为价格）。
* **`priceReconciliation`**：对账数据，包括传入的总价及明细、系统计算出的总价及明细、以及是否对账失败的对比结构。
* **`hotelTaxRateCodes`**：该酒店绑定的税率编码字串（如 `VAT,SERVICE`）。
* **`dailyTaxBreakdown`**：每日的税额与服务费拆分明细（包括日期、原始价、含税最终价、算出的增值税 VAT、算出的服务费 SERVICE 及其对应的税率值）。

### 3.2 房态与库存可用性检查 (InventoryDeductionServiceImpl.checkAvailability)
在预订库存与可用性检测阶段，必须留存：
* **`availabilityCheck`**：包含请求房量、入住/离店日期、房型与渠道、以及最少剩余数 `overallMin`、首个拦截原因 `firstRejectReason` 和每日的详细配额与 PMS 可售数列表（`dailyDetails`）。
* **`inventoryDeduct`**：扣减库存动作的实体属性（租户 ID、酒店、房型、房量、起止日期）。

### 3.3 支付确认与超时处理 (ReservationService & Job)
* **`payReservationDecision`**：支付回调发生时，记录获取悲观锁前后的状态。包含订单总价、支付传入金额、流水号 `transactionId`、幂等校验结果及原订单状态。
* **`cancelBySystemDecision`**：超时自动取消扫描发生时，记录订单的 `paymentDeadline`、触发取消时的时间戳以及是否符合取消条件的判定。

## 4. 前端异常感知与上报规范

前端在网页运行期间，必须具备静默感知和主动上报机制：

### 4.1 异常监听机制
* **JS 运行时报错**：通过全局监听 `window.addEventListener('error')` 捕获。
* **异步异常**：通过 `window.addEventListener('unhandledrejection')` 捕获未处理的 Promise 拒绝。

### 4.2 关联追踪上报
* **上报字段**：错误信息 `message`、发生脚本 `filename`、错误行号 `lineno`、列号 `colno`、错误堆栈 `stack`、当前浏览地址 `url`、浏览器 UserAgent。
* **MDC 级关联**：在 Axios 每次请求时，将当前生成的 traceId 暂存在 `sessionStorage` 的 `crs_last_trace_id` 键中。上报前端报错时，自动读取此 traceId 并封装入参数。
* **传输协议**：前端通过 `POST /api/trace/report` 异步上报，后端接收后统一写入 `SystemTraceLog` 表中（标记 `sourceType = FRONTEND`，`status = ERROR`）。

## 5. 诊断追踪控制台功能 (System Trace Console)

报表工作台下新增“系统诊断追踪控制台”菜单，提供可视化的排查界面：

### 5.1 多维度查询与还原
* 支持输入 `traceId` 查询单次调用的完整时序。
* 支持输入 `reservationCode`（订单号）查询与该订单相关的所有时序（例如“下午2:00下单 -> 下午2:10渠道回调支付 -> 下午2:30后台修改 -> 隔天入住”的完整链路日志）。

### 5.2 决策链路时序图 (Time-Line View)
* 以 Ant Design 时间轴呈现在该 traceId 下，从前端发起、网关拦截、核心价格决策、库存扣减到异步取消的每一个原子节点。
* 节点通过颜色标识状态：**SUCCESS (绿色)**、**BLOCKED_BY_RULE (黄色)**、**ERROR (红色)**。
* 节点提供展开抽屉，支持以树结构格式化呈现当前的 `DecisionSnapshot` 的 JSON 内容。

### 5.3 AI 一键诊断联动 (AI Diagnose)
* 当出现故障或价格争议时，用户点击节点上的“AI诊断”按钮。
* 系统自动根据当前 Trace 的异常堆栈、出错代码类与具体行数、绑定的 PRD 规范文档路径，以及全套决策快照 JSON 组装成标准诊断 Prompt。
* 提供“复制 Prompt 并打开 AI 诊断”按钮，直接复制 Prompt，供运维人员发送给 AI 助手进行故障自动复盘和秒级根因诊断。

## 6. 功能实现状态说明

截至 2026-06-06，本系统已 100% 完整实现“全系统链路追踪与 AI 诊断”底座，并通过静态构建打包测试：
* **链路标识传播**：前端 Axios 请求拦截器自动生成并在 `X-Trace-Id` 头部和 `crs_last_trace_id` 的 SessionStorage 携带 Trace ID，后端由拦截器、过滤器绑定 `MDC` 及 `ThreadLocal` 变量传递，在 `afterCompletion` 执行 `clear` 释放。
* **业务白盒决策快照**：在 `OpenReservationController` (订单创建与价格链计算)、`InventoryDeductionServiceImpl` (房态及库存校验扣减)、`ReservationService` & `ReservationPaymentTimeoutJob` (支付确认和支付超时任务) 等四个关键原子阶段打点快照。
* **前端异常感知与异步上报**：通过 `errorTracker` 全局静默收集 JavaScript Error 及未处理 Promise Rejection，关联最近 Trace ID 后上报到 `POST /api/trace/report` 并记录于 `SystemTraceLog` 中。
* **诊断控制台与 JSON 树交互**：实现 `SystemTraceConsole`，由居中 Modal 弹窗优化重构为右侧展开抽屉 `Drawer`，级联关系改由 `traceApi.getTraceDetail` 从后端拉取以解决 referenceCode 搜索的级联缺陷，并利用 `JsonTreeNode` 彩色高亮和折叠支持对决策快照进行可视化呈现。
