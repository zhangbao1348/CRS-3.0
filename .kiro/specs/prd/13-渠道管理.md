# 渠道管理

渠道管理是 CRS 系统的核心业务模块，负责管理集团/租户与各 OTA 渠道的对接配置、产品发布和映射关系。

渠道管理包含以下菜单：渠道列表、渠道映射。

---

## 1. 渠道列表

### 1.1 渠道卡片展示 ✅ 已实现

以卡片形式展示租户的所有可对接渠道，分为"已连接渠道"和"可连接渠道"两个 Tab。

数据来源：`tenant_channels` 表，通过 `connected` 字段区分已连接/可连接，按 `sort_order` 排序。

每个渠道卡片展示：
- 渠道 LOGO（160x160 图片区域，优先使用本地图片，回退到 logo_url）
- 渠道名称
- 连接状态标签：已连接显示绿色"20产品在售"，未连接显示蓝色"未连接"

后端 API：`GET /api/tenant-channels?tenantId=1` 返回 `{ connected: [...], available: [...] }` 分组数据。

### 1.2 渠道卡片点击跳转 ✅ 已实现

点击已连接的渠道卡片，根据通道类型跳转到对应的渠道详情页：

| 通道类型 | 跳转行为 |
|---------|---------|
| 携程（CTRIP）专属 | 跳转到 `/channel-management/ctrip-setting` |
| 飞猪（FLIGGY）专属 | 跳转到 `/channel-management/fliggy-setting` |
| switch_channel = Real_Time_API | 跳转到 `/channel-management/channel-setting/:channelCode` |
| 其他未对接渠道 | 不响应点击 |

跳转逻辑：先检查是否有专属路由（channelRouteMap），再检查 switchChannel 是否为 Real_Time_API，都不满足则不可点击。

## 2. 渠道详情页（通用渠道）✅ 已实现

当渠道的通道类型（switch_channel）为 `Real_Time_API` 时，点击渠道卡片跳转到通用渠道详情页（ChannelSetting.jsx）。

页面通过 URL 参数中的渠道代码（channelCode）加载对应渠道数据。

页面顶部显示返回按钮、渠道名称和面包屑导航"渠道管理 > 渠道详情"。

包含两个 Tab：基础信息、渠道发布。

后端 API：
- `GET /api/tenant-channels/code/:channelCode?tenantId=1` 获取渠道详情
- `PUT /api/tenant-channels/code/:channelCode?tenantId=1` 保存渠道配置

### 2.1 基础信息 Tab ✅ 已实现

#### 基础信息卡片
- 渠道名称（只读，disabled）
- 渠道代码（只读，disabled）
- 通道类型（只读，disabled）

#### 接口配置卡片
- 对接 Key（可编辑，来源 tenant_channels.access_key）
  - **展示逻辑**：若当前渠道为直销小程序（channelCode = 'WXMINI'），则整张卡片隐藏，不展示对接参数。
- **安全规则**：对接秘钥（access_secret）不在前端界面进行任何形式的回显、展示或配置，确保敏感认证信息不暴露。

#### 价格设置卡片
- 同步价格取整方式：Radio 单选（保持原值 / 向上取整 / 向下取整），存储字段 price_rounding
- 当渠道通道类型为实时接口（Real_Time_API）时，开放接口返回的价格字段需应用当前渠道的 `price_rounding` 规则；至少包括每日价格、总价和均价。

注：价格模式（单双同价/多人价）为标准渠道（携程/飞猪）专属配置，通用渠道不包含此项。

#### 订单规则卡片
- **预付订单是否需要支付**：Radio 单选（是 / 否），存储字段 `prepaid_order_requires_payment`
  - 选择“是”时：若价格计划绑定的担保政策类型为 `prepaid`，开放接口创建订单后进入 `pending_payment`，并生成 30 分钟后的 `paymentDeadline`
  - 选择“否”时：即使价格计划绑定 `prepaid`，开放接口创建订单也直接进入 `confirmed`，不生成 `paymentDeadline`
- **取消订单是否校验取消规则**：Radio 单选（是 / 否），存储字段 `cancel_order_checks_cancellation_rule`
  - 选择“是”时：开放接口取消订单继续按订单快照中的取消政策做校验
  - 选择“否”时：开放接口取消订单跳过取消政策校验，直接执行取消
- 两个开关默认值均为“是”，仅对当前渠道生效

#### 佣金设置卡片
- 预付佣金：佣金类型下拉框（百分比/固定金额）+ 数值输入框
- 现付佣金：佣金类型下拉框（百分比/固定金额）+ 数值输入框

存储字段：prepaid_commission_type、prepaid_commission_value、postpaid_commission_type、postpaid_commission_value

#### 保存设置
- 页面右上角"保存设置"按钮，提交表单数据到后端 API
- 保存中按钮显示 loading 状态，成功/失败显示对应提示
- 当当前渠道 `connected=0`（未连接）时，点击“保存设置”并保存成功后，系统需自动将该渠道更新为 `connected=1`（已连接）
- 当当前渠道已是 `connected=1` 时，点击“保存设置”仅更新配置字段，不重复改写连接状态

### 2.2 渠道发布 Tab ✅ 已实现

渠道发布功能按租户+酒店+渠道隔离，所有渠道通用。

**多维联动规则**：
- 页面订阅全局 `HotelContext`。当顶部 Header 切换酒店时，本页面数据（房价码、已发布记录）必须实时刷新。
- 顶部 Header 当前选中的酒店必须按租户维度持久化；用户刷新页面后，优先恢复该租户上次选中的有效酒店；若本地无有效酒店或该酒店已失效/不存在，则回退到酒店列表第一个。
- 切换酒店后，之前选中的房价码和房型状态必须清空，确证无跨酒店数据污染。

数据来源：
- 房价码列表从 `rate_plans` 表按当前酒店 ID 获取（仅 active 状态）
- 关联房型从 `hotel_room_types` 表获取，通过 rate_plan 的 `applicableRoomTypes` JSON 字段关联
- applicableRoomTypes 可能存储 hotel_room_types.id 或 groupRoomTypeId，后端同时用两个维度匹配

后端 API：
- `GET /api/channel-publish/rate-codes?hotelId=1` 或 `GET /api/channel-publish/rate-codes?hotelCode=JJSH001` 获取房价码及关联房型（两种参数二选一）
- `GET /api/channel-publish/records?tenantId=1&hotelCode=XXX&channelCode=XXX` 获取已发布记录
- `POST /api/channel-publish/batch` 批量发布

### US-13-01：Real_Time_API 渠道发布可选房价码/房型回显
**作为** 酒店管理员，**我希望** 在通用渠道（switch_channel=Real_Time_API）的“渠道发布”页能看到可选的房价码与房型，**以便** 我能把已分配到酒店的房价与房型发布到直销渠道。

**AC-13-01-1：** 当页面使用酒店 CODE（hotelCode）请求可选房价码时，后端必须能正确解析并返回该酒店的房价码列表与房型列表。  
**AC-13-01-2：** 返回结果仅包含当前酒店下 active 状态的房价码（rate_plans）与房型（hotel_room_types）。  
**AC-13-01-3：** 若仅传 hotelCode 且酒店不属于当前租户，接口返回 403。  

#### 房价码搜索与列表
- 顶部搜索框，按房价码名称或代码实时模糊过滤
- 房价码列表，每项包含勾选框、房价码名称和代码，格式：`名称 (代码)`
- 每个房价码下方展示关联房型列表，每个房型带独立勾选框，格式：`房型名称(房型代码)`

#### 房价码和房型选择
- 每个房价码的房型选择独立管理（selectedRoomTypesMap），不同房价码之间不联动
- 勾选房价码后，其下方房型勾选框才可用
- 未勾选的房价码，其房型勾选框禁用
- 底部显示已选择的房价码数量和房型总数量

#### 已发布记录回显
- 页面加载时从后端获取已发布记录（channel_publish_records 表）
- 自动回显已发布的房价码和房型的选中状态

#### 批量发布
- "批量发布"按钮
- 未选择房价码时提示"请选择至少一个房价码"
- 未选择房型时提示"请选择至少一个房型"
- 发布时按每个房价码独立发送各自选中的房型（rateCodeRoomTypesMap 格式）
- 发布保存前，后端需自动确保当前租户下该渠道与酒店的 `channel_hotel_mappings` 映射存在；若不存在则自动创建，若已存在但为停用则自动激活
- 自动创建 `channel_hotel_mappings` 时，必须完整写入 `tenant_id`、`channel_id`、`channel_code`、`channel_name`、`hotel_id`、`hotel_code`、`hotel_name`、`channel_hotel_code`，避免因必填关联字段缺失导致保存失败
- 发布成功后显示已发布的房价码数量和房型数量

## 4. 数据库设计

### 4.1 tenant_channels 表（租户可对接渠道表）✅ 已创建

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT | 主键 |
| tenant_id | INT | 租户ID |
| channel_name | VARCHAR(100) | 渠道名称 |
| channel_code | VARCHAR(50) | 渠道代码（tenant_id + channel_code 联合唯一） |
| connected | TINYINT(1) | 是否已对接：0-未对接，1-已对接 |
| logo_url | VARCHAR(500) | 渠道LOGO地址 |
| switch_channel | VARCHAR(50) | 通道类型（debi/changlian/Real_Time_API） |
| access_key | VARCHAR(200) | 对接key |
| access_secret | VARCHAR(500) | 对接秘钥 |
| sort_order | INT | 排序序号 |
| status | VARCHAR(20) | 状态：active/inactive |
| price_rounding | VARCHAR(20) | 价格取整方式：keep/ceil/floor，默认 keep |
| prepaid_order_requires_payment | TINYINT(1) | 预付订单是否需要支付：0-否，1-是，默认 1 |
| cancel_order_checks_cancellation_rule | TINYINT(1) | 取消订单是否校验取消规则：0-否，1-是，默认 1 |
| prepaid_commission_type | VARCHAR(20) | 预付佣金类型：percentage/fixed，默认 percentage |
| prepaid_commission_value | DECIMAL(10,2) | 预付佣金数值 |
| postpaid_commission_type | VARCHAR(20) | 现付佣金类型：percentage/fixed，默认 percentage |
| postpaid_commission_value | DECIMAL(10,2) | 现付佣金数值 |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

**索引优化**：
- `idx_tenant_channel_code`: (tenant_id, channel_code)

### 4.2 channel_publish_records 表（渠道发布记录表）✅ 已创建
