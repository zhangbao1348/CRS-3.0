# 价格计划管理

价格计划管理是 CRS 系统的酒店端价格管理模块，负责酒店级别的价格计划维护、基础价格设置和价格查询。价格计划管理的数据以当前选中的酒店为上下文，切换酒店后数据自动刷新。

价格计划管理包含以下菜单：价格计划、基础价格设置、包价设置、价格查询。

**全局代码字段规则：** 本模块中所有"代码"类字段统一只允许输入英文字母、数字和下划线。

## 2. 基础价格设置

### 2.1 价格日历 ✅ 已实现

基础价格设置以日历矩阵形式展示和编辑各房型在各日期的价格。

页面顶部有以下控件：
- **价格码选择**：下拉选择，仅显示基础房价码（衍生码的价格由系统自动计算，不支持手动设置），显示格式为"名称（代码）"
- **月份选择**：月份选择器，默认当前月
- **查询按钮**：点击后加载价格数据
- **批量修改按钮**：打开批量设价弹窗
- **日志按钮**：打开价格操作日志弹窗

价格矩阵以表格形式展示：
- 列：日期（当月每天一列），表头显示日期和星期，周末日期标红
- 行：每个房型一行，显示该房型在各日期的含税价格
- 价格单元格可直接编辑，失焦时自动保存
- **不含税价联动随动计算**：当用户在基础价格中保存某日价格（单格编辑或批量设价）导致 `priceWithTax`（含税价）发生变更时，系统将自动检索当前酒店绑定的所有有效集团税率（如增值税 6% + 服务费 10% = 16%），并使用公式 $priceWithoutTax = priceWithTax / (1 + 税率总和)$ 重新计算该日期的不含税售价，四舍五入保留两位小数并同步持久化入库，保障双价格维度的绝对精确与合规。
- 若当前酒店维护了“酒店最低价格（含税）”，则任一日期保存的 `priceWithTax` 不得低于该最低价；输入更低值时系统自动按酒店最低价格（含税）保存并依据该最低含税价计算对应的不含税价落库。
- 已删除的价格（status=inactive）在不可编辑日期显示"-"；若日期仍处于可编辑窗口内，则应继续提供输入框，允许直接恢复录入价格。
- 房型列左侧固定，日期列可横向滚动
- 当所选月份为当前月时，查询完成后页面需自动横向定位到今天所在列，减少手动滚动成本。
- 历史日期默认不可修改；仅在每天 `00:00-06:00` 时间窗口内允许补改昨天价格，更早日期统一禁用。

### 2.2 批量设价 ✅ 已实现

通过弹窗表单进行批量价格设置：

- **日期范围**（必填）：日期范围选择器
- **周控**：多选复选框（周一至周日），支持全选，选择适用的星期几
- **房型与价格**：每个房型独立一行，每行包含：
  - 房型名称（代码）
  - 含税价格输入框（不填则不更新该房型）
  - "删除"复选框（勾选后价格输入框禁用，保存时将删除该房型在所选日期范围内的价格）

不同房型可设置不同价格。确认后批量更新选中日期范围内、选中星期、选中房型的价格。
- 批量设价中的日期范围需遵循与单格编辑一致的可编辑规则：默认仅允许今天及未来日期；每天 `00:00-06:00` 允许选择昨天；更早日期采用禁用态不可选。

点击"日志"按钮弹出价格操作日志弹窗，展示当前酒店和价格码下的价格变更记录。

日志列表展示以下信息：

| 列 | 说明 |
|----|------|

| 操作人 | 执行操作的用户名 |
| 操作类型 | 新增（绿色）/ 修改（蓝色）/ 删除（红色）/ 批量修改（蓝色）/ 批量删除（红色） |

## 3. 包价设置（酒店端）

### 3.1 酒店包价列表 ✅ 已实现

展示当前酒店可用的包价列表。酒店端的包价来源于集团包价设置，酒店可以在此查看和管理本酒店的包价。

列表结构和筛选条件与集团包价设置一致，参见集团管理 PRD 第 10 节。

酒店包价列表页必须直接读取真实包价数据，不允许使用前端写死的模拟列表作为正式展示数据源。列表数据通过包价接口返回，并按当前登录租户进行隔离。

列表页展示规则如下：

| 列 | 规则 |
|----|------|
| 包价名称 | 显示 `name` |
| 包价代码 | 显示 `code` |
| 包价类型 | 显示 `type` |
| 包价价格 | `fixedPrice` 有值时显示为 `¥金额`；`priceType=daily` 时显示可点击的“设置价格”；`fixedPrice` 为空且 `priceType=group` 时显示“集团设置”；其他异常历史数据统一显示 `-` |
| 描述 | 显示 `description` |
| 状态 | `active` 显示“启用”（绿色）；`inactive` 显示“停用”（红色） |

酒店包价列表页的查询条件包括：包价名称、包价代码、包价类型、状态。各条件支持组合筛选，返回结果必须与数据库当前数据一致。

酒店包价列表页的包价类型筛选选项需与新增/编辑页保持一致，统一为：早餐 / 午餐 / 晚餐 / 综合 / 下午茶 / 门票 / 其他 / 免费增早 / 延时退房 / 提前入住。

酒店包价新增/编辑页中的“发放频率”字段前端需显示中文名称（如“每天1次”），但提交与回显应统一使用标准编码值（`daily`、`per_stay`、`arrival_day`、`departure_day`、`except_departure`）；若历史数据仍为中文值，编辑回显时需自动兼容映射为对应编码后再展示中文选项。

当酒店包价 `priceType=daily` 时，列表页“包价价格”列必须显示可点击的“设置价格”。点击后进入当前包价的每日价格设置区域，按当前登录租户 + 当前选中酒店 + 包价代码加载并维护该包价的每日价格。

### 3.2 酒店包价新增/编辑 ✅ 已实现

酒店端包价新增/编辑页提交与回显规则如下：

- **计数方式**（必填）：固定选项包括固定份数、按订单、按房间、按人数、按成人数、按儿童数。
- **份数字段**（必填）：无论选择哪一种计数方式，前端统一提交到 `fixedQuantity` 字段持久化，不再拆分为 `perOrderQuantity`、`perRoomQuantity`、`perPersonQuantity` 等临时字段。
- **份数字段标签**：根据 `quantityType` 动态显示为“固定份数”“每订单份数”“每房间份数”“每人份数”“每成人份数”“每儿童份数”。
- **编辑回显**：详情接口返回的 `fixedQuantity` 必须回填到当前计数方式对应的份数输入框。
- **价格方式**：酒店端仅支持“固定价格”“按日期设置价格”两种方式。
- **固定价格规则**：选择“固定价格”时提交 `fixedPrice`，并提交 `priceType=group`。
- **按日期设置价格规则**：选择“按日期设置价格”时清空 `fixedPrice`，并提交 `priceType=daily`。保存成功后可进入“每日价格设置”区域按天维护价格。
- **包价类型选项**：酒店端新增/编辑页与列表筛选页保持一致，统一为：早餐 / 午餐 / 晚餐 / 综合 / 下午茶 / 门票 / 其他 / 免费增早 / 延时退房 / 提前入住。
- **接口调用规范**：酒店端新增/编辑包价必须通过 `src/utils/api.js` 统一请求客户端访问后端接口。

### 3.3 酒店包价每日价格设置 ✅ 本次实现

当酒店包价的价格方式为“按日期设置价格”时，酒店端需要支持按月维护该包价的每日价格。

页面规则如下：

- 顶部显示当前包价名称、包价代码、当前酒店、月份选择器、批量修改按钮。
- 默认按当前月加载每日价格，切换月份后自动刷新当月数据。
- 以月历矩阵展示当月每天，按“周日到周六”七列排布，按周换行显示。
- 每个日期单元格支持直接输入价格，保留 2 位小数。
- 单个日期价格在输入框失去焦点时自动保存，并提示“保存成功”。
- 清空某天价格后，输入框失去焦点时删除该日期对应的价格记录。
- 仅当包价 `priceType=daily` 时显示该配置区域；非按日期设置价格的包价不展示每日价格编辑区域。

批量修改规则如下：

- 点击“批量修改”按钮后弹出批量修改弹窗。
- 弹窗字段包括：日期段、周控、价格。
- 周控使用 7 个星期多选框展示，并提供“全选”。
- 周控默认全选全部星期。
- 用户保存后，将价格批量覆盖到命中的日期。
- 批量修改成功后关闭弹窗，并刷新当前月份的日历矩阵数据。

每日价格数据存储规则如下：

- 以 `tenant_id + hotel_code + package_code + price_date` 作为唯一业务维度。
- 每日价格仅对当前选中酒店生效，不跨酒店共享。
- 保存接口支持批量提交一个月内的多个日期价格，后端按日期做新增、更新或删除。

## 4. 价格查询

### 4.1 价格查询页面 ✅ 已实现

价格查询以月度日历矩阵只读查看各房型在各价格计划下的每日含税价格。

页面顶部有以下控件：
- **价格计划选择**：下拉选择，数据来源于当前酒店的价格计划列表，显示格式为"名称（代码）"，默认选中第一个价格计划
- **月份选择**：月份选择器，默认当前月
- **查询按钮**：点击后加载价格数据
- **重置按钮**：重置为默认月份和第一个价格计划

价格矩阵以表格形式展示：
- 列：日期（当月每天一列），表头显示日期（MM-DD）和星期
- 行：每个房型一行，显示该房型在选中价格计划下的每日含税价格
- 周末日期（周六、周日）表头标红，单元格浅黄色背景
- 有价格的单元格显示"¥金额"
- 无价格的单元格为空
- 已删除的价格（status=inactive）显示"-"
- 房型列固定在左侧，日期列可横向滚动
- 查询成功后，如所选月份为当前月，页面需优先自动横向定位到今天所在列；如所选月份不是当前月，仍可在首个有价日期不在初始可视区域时自动横向定位到首个有价日期，避免误判为无价格数据。
- 当所选价格计划和月份没有任何价格记录时，页面显示“所选条件暂无价格数据”，不展示整月空白矩阵。
- 页面内所有日期选择器、月份面板和星期显示必须使用中文，不允许出现 `Jan`、`Feb`、`Mon`、`Tue` 等英文月份或星期文案。
- **价格显示切换**：支持“含税价”和“不含税价”的 Radio 单选按钮切换，默认显示“含税价”。切换后表格内的金额需立即转为所选的计价类型，保留 2 位小数（统一为 `¥XX.XX` 双精度财务格式），提供 0 延迟无闪烁的用户体验。

价格查询为只读页面，不支持编辑。数据来源于 hotel_prices 表。

酒店包价新增/编辑页展示规则如下：

- 页面仍挂载在“价格计划管理 > 包价设置”菜单下。
- 进入新增页或编辑页时，左侧“价格计划管理”父菜单需保持展开，“包价设置”保持当前归属高亮。
- 编辑页整体布局与价格计划编辑页保持一致，采用页面标题 + 返回按钮 + 卡片式表单容器的视觉结构，避免独立窄表单样式突兀。

## 5. 酒店价格表

酒店价格表用于存储酒店每日的实际售价，按租户 + 酒店 + 房价码 + 房型 + 日期维度存储。

**数据结构：**

| 字段 | 说明 |
|------|------|
| 租户ID | 所属租户 |
| 酒店CODE | 所属酒店 |
| 房价码CODE | 关联的房价码/价格计划 |
| 房型CODE | 关联的房型 |
| 日期 | 价格适用日期 |
| 含税价格 | 含税售价，精度 2 位小数 |
| 不含税价格 | 不含税售价，精度 2 位小数 |
| 状态 | active（有效）/ inactive（已删除） |

**唯一约束：** 同一租户 + 酒店 + 房价码 + 房型 + 日期的组合不可重复。

## 价格计算逻辑

酒店端的最终售价由以下因素计算：

1. **基础价格**（hotel_prices 表）：按租户 + 酒店 + 房价码 + 房型 + 日期维度存储的含税价格
2. **衍生折扣**：如果是衍生价格计划，在父级价格计划的最终价格基础上按折扣百分比计算

最终价格 = 基础价格 × 衍生折扣（如适用），按取整方式处理小数。
**不含税价随动重算机制**：只要有含税价格（无论基础价格或衍生价格）在任意场景下发生变更或计算写入，系统都会自动应用对应酒店绑定的集团税率，按公式 $priceWithoutTax = priceWithTax / (1 + 税率总和)$ 随动重新计算并不失精度地四舍五入保存不含税售价，以保障多税率场景下两套计价的精确闭环。

### 衍生价格自动计算（下发时） ✅ 已实现

当衍生房价码从集团下发到酒店时，系统自动根据父级房价码在该酒店已有的价格数据计算衍生价格。

**触发条件：** 集团管理员在房价码分配页面将衍生房价码（一级或二级）分配到酒店

**计算流程：**
1. 系统查找父级房价码在该酒店的所有 active 状态的价格记录
2. 对每条父级价格记录，按衍生码配置的折扣百分比计算衍生价格
3. 按衍生码配置的取整方式处理小数：
   - 四舍五入：保留两位小数（默认）
   - 向下取整：取整数，舍去小数
   - 向上取整：取整数，小数进位
4. 将计算结果写入 hotel_prices 表（已存在则更新，不存在则新增）
5. 如果父级房价码在该酒店无价格数据，则不生成衍生价格，不报错
6. 如果酒店维护了“酒店最低价格（含税）”，则衍生计算结果若低于该最低价，需自动抬升为酒店最低价格（含税）

**示例：**
- 基础房价码 RACK 在酒店 A 的豪华大床房 2026-05-01 价格为 ¥500
- 一级衍生码 WEEKEND 折扣为 90%，取整方式为四舍五入
- 下发 WEEKEND 到酒店 A 时，自动生成：豪华大床房 2026-05-01 价格 = ¥500 × 90% = ¥450.00

### 衍生价格级联更新（价格变更时） ✅ 已实现

当酒店端修改基础价格时，系统自动级联更新所有关联的衍生码价格，支持多级递归。

**触发条件：**
- 单条价格编辑（单元格失焦保存）
- 批量价格设置（批量修改弹窗保存）
- 批量价格删除（批量删除操作）

**级联更新流程：**
1. 用户修改房价码 A 的某个房型在某个日期的价格
2. 系统查找同一酒店下所有以房价码 A 为父级（parentRateCode = A）的 active 状态衍生价格计划
3. 对每个一级衍生码，按其折扣百分比和取整方式计算新价格，更新到 hotel_prices 表
4. 对每个一级衍生码，继续查找以该一级衍生码为父级的二级衍生码
5. 对每个二级衍生码，基于一级衍生码的新价格（而非基础价格），按其折扣百分比和取整方式计算新价格
6. 递归处理直到没有更多下级衍生码
7. 任一级联计算结果若低于酒店最低价格（含税），则按酒店最低价格（含税）落库

**级联删除流程：**
- 当基础价格被删除（标记为 inactive）时，对应的一级衍生码价格也被级联删除
- 一级衍生码价格被删除时，对应的二级衍生码价格也被级联删除

**示例：**
- 基础房价码 RACK，豪华大床房 2026-05-01 原价 ¥500，修改为 ¥600
- 一级衍生码 WEEKEND（折扣 90%）：¥600 × 90% = ¥540
- 二级衍生码 WEEKEND_VIP（折扣 85%，基于 WEEKEND）：¥540 × 85% = ¥459

**注意事项：**
- 级联计算在价格保存时同步执行，无需手动触发
- 只影响同一酒店、同一房型、同一日期的衍生价格
- 只处理 active 状态的衍生价格计划，已停用的衍生码不参与计算
- 衍生码的折扣和取整方式以衍生码自身的配置为准

### 集团修改衍生码折扣/取整方式时的价格重算 ✅ 已实现

当集团管理员修改了衍生房价码的折扣或取整方式，并同步到酒店时，系统会自动重新计算该衍生码在所有受影响酒店的价格。

**触发条件：** 集团管理员修改衍生房价码的折扣百分比或取整方式，保存后选择同步到酒店

**计算流程：**
1. 系统检测到同步的衍生码折扣或取整方式与酒店端之前的值不同
2. 查找父级房价码在该酒店的所有 active 价格记录
3. 按新的折扣和取整方式重新计算所有衍生价格
4. 更新到 hotel_prices 表

**示例：**
- 集团衍生码 WEEKEND 原折扣 90%，修改为 85%
- 同步到上海锦江饭店后，该酒店 WEEKEND 的所有价格按 85% 重新计算
- 比如父级 RACK 豪华大床房 5月1日 ¥500，原衍生价 ¥450（90%），重算后变为 ¥425（85%）
