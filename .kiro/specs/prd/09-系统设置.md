# 系统设置

系统设置是 CRS 系统的基础管理模块，负责用户账号、角色权限和集团参数的配置管理。

系统设置包含以下菜单：用户管理、角色管理、集团设置、字典管理。

**全局代码字段规则：** 本模块中所有"代码"类字段（角色代码、渠道代码等）统一只允许输入英文字母、数字和下划线（_），正则表达式：`^[A-Za-z0-9_]+$`。

**登录页体验要求：**
- 登录页采用品牌化视觉风格，需体现酒店集团中后台的专业感、稳定感与安全感。
- 表单字段必须提供可见标签，不可仅依赖 placeholder 作为字段说明。
- 登录按钮、输入框、错误提示与默认账号提示需具备清晰层级，保证首屏可读性与易操作性。
- 在桌面端和移动端下均需保持表单主操作区域完整可见，不出现遮挡、水平滚动或输入区域拥挤问题。

**顶部租户切换稳定性要求：**
- 超级管理员右上角的租户切换下拉使用租户列表接口 `/api/tenants` 作为数据源。
- 当页面初始化期间后端处于热重启或短暂不可用状态时，前端需优先使用本地缓存的租户列表与已选租户名称进行兜底展示，避免下拉框显示裸数字租户 ID。
- 租户列表接口恢复后，前端需自动用最新接口结果刷新缓存，并继续保持当前已选租户的正确显示。

## 1. 用户管理

### 1.1 用户列表 ✅ 已实现

展示系统中所有用户。页面顶部为查询区域，支持按以下条件筛选：

- 用户名（模糊匹配）
- 姓名（模糊匹配）
- 状态（下拉选择，启用/禁用）
- 归属（下拉选择，平台或具体租户）

列表展示以下信息：

| 列 | 说明 |
|----|------|
| 归属 | 平台（蓝色）或租户名称（绿色） |
| 用户名 | 登录账号 |
| 姓名 | 用户真实姓名 |
| 邮箱 | 用户邮箱 |
| 手机号 | 用户手机号 |
| 角色 | 用户拥有的角色，以紫色标签展示，支持多角色 |
| 状态 | 启用（绿色标签）/ 停用（红色标签） |
| 创建时间 | 用户创建时间 |
| 操作 | 编辑、重置密码、启用/禁用、删除 |

列表右上方有"新增用户"按钮。

### 1.2 新增/编辑用户 ✅ 已实现

通过弹窗表单进行新增和编辑，包含以下字段：

- **归属**（选填）：下拉选择，选项为"平台"或具体租户。不选则为平台用户
- **用户名**（必填）：用户输入，编辑时不可修改
- **姓名**（必填）：用户输入
- **邮箱**（必填）：用户输入，需符合邮箱格式校验
- **手机号**（选填）：用户输入
- **密码**（必填，仅新增时显示）：密码输入
- **角色**（必填）：多选复选框，从系统角色列表中选择

### 1.3 重置密码 ✅ 已实现

通过弹窗表单进行密码重置：

- **新密码**（必填）：密码输入，最少 6 位
- **确认密码**（必填）：密码输入，需与新密码一致

### 1.4 其他操作 ✅ 已实现

- **启用/禁用**：点击后直接切换用户状态
- **删除**：需二次确认（Popconfirm）

## 3. 集团设置

### 3.1 集团参数配置 ✅ 已实现

集团设置页面用于配置集团级别的全局参数，影响集团下所有酒店的业务行为。

包含以下配置项：

- **集团管控模式**（必填）：单选，固定选项：强管控 / 弱管控
- **钟点房**（必填）：单选，固定选项：支持 / 不支持
- **OTA 促销模式**（必填）：单选，固定选项：集团报名 / 集团设置规则酒店报名 / 酒店自行管理
- **预测价格显示配置**：多选复选框
  - 显示携程预测价格
  - 显示美团预测价格

页面底部有"保存设置"按钮。

注：当前集团设置数据存储在 localStorage 中，未对接后端 API。

## 4. 字典管理

### 4.1 模块定位

字典管理用于统一维护系统中“可配置、可复用、跨模块共享”的基础选项数据，放置于 `系统设置` 菜单下。

该模块主要服务于各类杂项下拉、状态、标签、分类等非强规则业务枚举，不替代后端代码中已固化的强业务枚举（如税规则、货币、系统内部状态常量）。

### 4.2 用户故事

### US-SS-04：维护系统可配置字典
**作为** 集团管理员，**我希望** 在系统设置下统一维护字典类型和字典项，**以便** 各业务模块可以复用统一的下拉选项和配置值。

### 4.3 页面结构

字典管理页面采用左右分栏结构：

- 左侧：字典类型列表
- 右侧：当前选中字典类型下的字典项列表

页面支持：

- 查询字典类型
- 新增/编辑/停用/删除字典类型
- 查询字典项
- 新增/编辑/停用/删除字典项
- 调整字典项排序

### 4.4 字典类型字段

| 字段 | 必填 | 类型 | 说明 | 默认值 |
|------|------|------|------|--------|
| 类型名称 `typeName` | 是 | 文本 | 用于页面展示 | - |
| 类型编码 `typeCode` | 是 | 文本 | 业务唯一编码，仅允许字母/数字/下划线 | - |
| 描述 `description` | 否 | 多行文本 | 补充说明该字典用途 | 空 |
| 状态 `status` | 是 | 下拉 | `active` / `inactive` | `active` |
| 内置标识 `builtIn` | 否 | 布尔 | 标识是否为系统内置字典类型 | `false` |
| 排序 `sortOrder` | 否 | 数字 | 用于类型列表排序，数值越小越靠前 | `0` |

### 4.5 字典项字段

| 字段 | 必填 | 类型 | 说明 | 默认值 |
|------|------|------|------|--------|
| 项目名称 `itemName` | 是 | 文本 | 页面展示名称 | - |
| 项目编码 `itemCode` | 是 | 文本 | 当前字典类型内唯一，允许字母/数字/下划线 | - |
| 项目值 `itemValue` | 否 | 文本 | 默认与项目编码一致，可用于保留展示值与实际值差异 | 空 |
| 描述 `description` | 否 | 多行文本 | 该字典项补充说明 | 空 |
| 是否默认 `isDefault` | 否 | 开关 | 同一字典类型下最多允许一个默认项 | `false` |
| 状态 `status` | 是 | 下拉 | `active` / `inactive` | `active` |
| 排序 `sortOrder` | 否 | 数字 | 用于列表及下拉展示顺序 | `0` |

### 4.6 交互规则

**AC-SS-04-1：** 进入字典管理页面后，左侧默认加载当前租户下全部字典类型，并按 `sortOrder ASC, id ASC` 排序。

**AC-SS-04-2：** 选中字典类型后，右侧仅展示该 `typeCode` 下的字典项，并按 `sortOrder ASC, id ASC` 排序。

**AC-SS-04-3：** 新增字典类型时，`typeCode` 必须在当前租户内唯一，且只允许字母、数字和下划线。

**AC-SS-04-4：** 新增字典项时，`tenantId + typeCode + itemCode` 组合必须唯一。

**AC-SS-04-5：** [条件] 字典项 `isDefault=true` 时，同一 `typeCode` 下其他项必须自动更新为 `isDefault=false`。

**AC-SS-04-6：** 删除字典类型前，如其下仍存在字典项，则不允许删除，并提示“请先删除或停用该类型下的字典项”。

**AC-SS-04-7：** [条件] `builtIn=true` 时，字典类型不允许删除，但允许编辑名称、描述、状态和排序。

**AC-SS-04-8：** 对外提供按字典类型编码查询字典项的接口时，仅返回 `status=active` 的字典项。

**AC-SS-04-9：** 对外字典项查询接口返回字段统一包含：`code`、`name`、`value`、`sortOrder`。

**AC-SS-04-10：** 字典管理模块放置于 `系统设置 > 字典管理`，并纳入角色菜单权限树。

### 4.7 使用边界

- 适用于：可运营维护的业务选项、杂项枚举、扩展标签、原因类字典、来源类字典
- 不适用于：参与核心计算的强业务规则枚举、必须由代码保证一致性的系统常量

### 4.8 接口需求

- `GET /api/dictionary-types`
- `POST /api/dictionary-types`
- `PUT /api/dictionary-types/{id}`
- `DELETE /api/dictionary-types/{id}`
- `GET /api/dictionary-items?typeCode={typeCode}`
- `POST /api/dictionary-items`
- `PUT /api/dictionary-items/{id}`
- `DELETE /api/dictionary-items/{id}`
- `GET /api/dictionaries/{typeCode}/items`

### 4.9 菜单与权限

- 菜单位置：`系统设置 > 字典管理`
- 权限建议至少包含：
  - 查看字典管理
  - 新增/编辑/删除字典类型
  - 新增/编辑/删除字典项
