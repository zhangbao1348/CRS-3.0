## 一、概述

本文档定义了 CRS 中央预订系统面向小程序端的实时查询与预订接口。所有接口通过渠道秘钥（API Key + Secret）进行身份认证，数据按租户隔离。

### 接口清单

| 序号 | 接口名称 | 方法 | 路径 | 状态 |
|------|----------|------|------|------|
| 1 | 查询酒店列表 | GET | `/api/open/hotels` | [ ] 未实现 |
| 2 | 查询酒店详情与价格 | GET | `/api/open/hotels/{hotelCode}` | [ ] 未实现 |
| 3 | 可订检查 | POST | `/api/open/availability/check` | [ ] 未实现 |
| 4 | 创建订单 | POST | `/api/open/reservations` | [ ] 未实现 |
| 5 | 支付订单 | POST | `/api/open/reservations/{reservationCode}/pay` | [ ] 未实现 |

### 公共约定

- **Base URL**：`https://{domain}/api/open`
- **认证方式**：所有请求必须在 Header 中携带 `X-Api-Key` 和 `X-Api-Secret`，对应 `tenant_channels` 表的 `access_key` / `access_secret`
- **数据格式**：JSON（`Content-Type: application/json`）
- **日期格式**：`yyyy-MM-dd`（如 `2026-05-01`）
- **金额单位**：人民币元，保留两位小数
- **字符编码**：UTF-8

### 公共响应结构

```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": "2026-05-01T10:00:00+08:00"
}
```

### 公共错误码

| 错误码 | 含义 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 认证失败（Key/Secret 无效或渠道未连接） |
| 403 | 权限不足（渠道未被授权访问该酒店） |
| 404 | 资源不存在 |
| 409 | 库存不足或不可预订 |
| 500 | 服务器内部错误 |

### 接口 1：查询酒店列表

获取渠道可见的酒店列表，包含静态信息和起价。

- **方法**：`GET`
- **路径**：`/api/open/hotels`
- **状态**：[ ] 未实现

#### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| cityId | String | 否 | 城市筛选，对应 `hotels.city` |
| checkInDate | String | 否 | 入住日期（yyyy-MM-dd），用于计算起价和可用性 |
| checkOutDate | String | 否 | 离店日期（yyyy-MM-dd），与 checkInDate 配对使用 |
| keyword | String | 否 | 搜索关键词，模糊匹配酒店中/英文名称 |
| page | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页数量，默认 20，最大 50 |

#### 业务规则

1. 仅返回 `status = active` 的酒店
2. 仅返回已通过 `channel_hotel_mappings` 授权给当前渠道的酒店
3. 若传入 `checkInDate` 和 `checkOutDate`，则计算该日期范围内的最低起价（从 `hotel_prices` 表取含税价最低值）
4. 若未传入日期，起价字段返回 `null`
5. 起价计算需排除已关房（`room_status` 为 closed）的房型

### 接口 2：查询酒店详情与价格

获取单个酒店的完整信息，包含所有可售房型及每日价格。

- **方法**：`GET`
- **路径**：`/api/open/hotels/{hotelCode}`
- **状态**：[ ] 未实现

#### 路径参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| hotelCode | String | 是 | 酒店编码 |

#### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| checkInDate | String | 是 | 入住日期（yyyy-MM-dd） |
| checkOutDate | String | 是 | 离店日期（yyyy-MM-dd） |
| adultCount | Integer | 否 | 成人数，默认 2 |
| childCount | Integer | 否 | 儿童数，默认 0 |
| roomCount | Integer | 否 | 房间数，默认 1 |

#### 业务规则

1. 校验渠道是否有权访问该酒店（`channel_hotel_mappings`）
2. 仅返回 `status = active` 的房型（`hotel_room_types`）
3. 仅返回已关联到当前渠道且处于可售状态的价格计划（`rate_plans`）
4. 每日价格从 `hotel_prices` 表获取，日期范围为 `[checkInDate, checkOutDate)`
5. 库存从 `inventory` 表获取，取日期范围内的最小可用值
6. 房态检查：若该房型在 `room_status` 中的 `status = closed`，标记为不可订
7. 预订控制：从 `booking_controls` 获取提前预订天数、最少/最多入住天数等规则
8. 包价信息从 `rate_plan_packages` + `packages` 关联查询

### 接口 3：可订检查

下单前的实时可订检查，验证库存、房态、预订规则和价格。

- **方法**：`POST`
- **路径**：`/api/open/availability/check`

#### 请求体

```json

  "roomTypeCode": "STDK",
  "ratePlanCode": "BAR",
  "checkInDate": "2026-05-01",
  "checkOutDate": "2026-05-03",
  "roomCount": 1,
  "adultCount": 2,
  "childCount": 0
}
```

#### 请求字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| hotelCode | String | 是 | 酒店编码 |
| roomTypeCode | String | 是 | 房型编码 |
| ratePlanCode | String | 是 | 价格计划编码 |
| checkInDate | String | 是 | 入住日期 |
| checkOutDate | String | 是 | 离店日期 |
| roomCount | Integer | 是 | 房间数 |
| adultCount | Integer | 是 | 成人数 |
| childCount | Integer | 否 | 儿童数，默认 0 |

#### 业务规则（按优先级顺序校验）

1. **渠道权限**：校验渠道是否有权访问该酒店
2. **酒店/房型/价格计划有效性**：校验三者是否存在且 `status = active`
3. **房型适用性**：校验该价格计划的 `applicable_room_types` 是否包含目标房型
4. **房态检查**：校验入住期间每一天的 `room_status` 是否为 open
5. **库存检查**：校验入住期间每一天的 `inventory.available_rooms >= roomCount`
6. **入住人数**：校验 `adultCount <= hotel_room_types.max_adults`，`adultCount + childCount <= max_occupancy`
7. **提前预订天数**：校验 `checkInDate - today >= booking_controls.advance_booking_days`
8. **入住天数限制**：校验 `nights >= min_stay && nights <= max_stay`
9. **价格完整性**：校验入住期间每一天在 `hotel_prices` 中都有对应价格记录

| 值 | 说明 |
|----|------|

## 三、安全与性能要求

### 安全要求

1. **传输安全**：所有接口必须使用 HTTPS
2. **认证机制**：通过 `X-Api-Key` + `X-Api-Secret` 双重校验，对应 `tenant_channels` 表
3. **数据隔离**：所有查询和操作严格按 `tenant_id` 隔离
4. **渠道授权**：酒店数据仅对已通过 `channel_hotel_mappings` 授权的渠道可见
5. **敏感数据**：信用卡信息需加密传输和存储
6. **频率限制**：单渠道每秒最大请求数 100

### 性能要求

| 接口 | 目标响应时间 |
|------|-------------|
| 查询酒店列表 | ≤ 500ms |
| 查询酒店详情与价格 | ≤ 800ms |
| 可订检查 | ≤ 300ms |
| 创建订单 | ≤ 1000ms |
| 支付订单 | ≤ 500ms |

## 四、数据模型依赖

本接口涉及的核心数据表及其关系：

```
hotels                      -- 酒店主表
├── hotel_images             -- 酒店图片
├── hotel_facilities         -- 酒店设施
├── hotel_room_types         -- 酒店房型
│   ├── room_type_facilities -- 房型设施
│   └── hotel_prices         -- 房型每日价格（按 rate_plan）
├── rate_plans               -- 价格计划
│   ├── rate_plan_packages   -- 价格计划关联的包价
│   ├── cancellation_policies-- 取消政策（通过 cancellation_rule 关联）
│   └── guarantee_policies   -- 担保政策（通过 guarantee_rule 关联）
├── inventory                -- 库存（按 hotel+room_type+rate_plan+date）
├── room_status              -- 房态（开/关房）
├── booking_controls         -- 预订控制规则
├── channel_hotel_mappings   -- 渠道-酒店映射
└── reservation              -- 预订订单
```
