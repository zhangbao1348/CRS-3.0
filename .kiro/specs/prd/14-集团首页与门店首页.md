# 第一部分：业务规则 (Business Rules)

## 一、 功能概述

### 1.1 背景与目标
解决原有首页数据硬编码、指标不真实、角色关注点不明确的问题。通过数据驱动的双模式首页，为不同层级的管理人员提供实时的决策支持。

### 1.2 核心模式定义
系统根据用户当前的操作上下文自动切换展示模式：
- **集团模式 (Group Mode)**：当用户未选定具体酒店时展示。侧重于全集团酒店的横向对比、整体营收监控及跨酒店的库存预警。
- **门店模式 (Hotel Mode)**：当用户选定具体酒店时展示。侧重于单店的精细化运营，包含今日房态、实时订单、及未来一周的库存趋势。

---

## 二、 集团首页业务逻辑

### 2.1 核心运营指标
集团管理层需实时关注以下全量指标：
- **今日新订单**：今日零点至今全集团产生的所有新预订总量。
- **今日入住**：预定于今日抵店的全集团间夜量。
- **本月累计收入**：本月一日至今全集团所有有效预订的总金额。
- **活跃酒店数**：当前处于运营状态的酒店总数。
- **集团待处理事项**：全集团范围内需要人工干预的异常订单总量。

### 2.2 酒店业绩贡献榜 (Leaderboard)
- **排行维度**：支持按“本月营收”或“今日出租率”进行酒店排行。
- **目标**：识别集团内的标杆门店，并对表现不佳的门店进行及时干预。

### 2.3 集团全域流速趋势 (Group Pacing)
- **核心逻辑**：计算集团整体在未来 7 天的平均预订速度。
- **应用场景**：若全集团流速偏慢，可触发集团级的渠道促销活动。

### 2.2 酒店运营概览
以列表形式展示旗下各酒店的实时运营快照，包含酒店名称、城市、今日到客量、今日离店量、当日剩余可售房量及本月贡献营收。支持点击酒店名称快速切换至该门店的详情视图。

### 2.3 库存预警规则
系统需自动识别全集团范围内未来一周内库存极低的风险点。
- **预警阈值**：当任一酒店、任一房型在未来 7 天内的剩余可用库存小于或等于 2 间时，触发预警。
- **展示要求**：按时间顺序排列，优先展示最近发生的库存风险。

## 三、 门店首页业务逻辑

### 3.1 单店运营 KPI
门店运营人员需关注以下实时指标：
- **实时到客与离店**：今日计划抵店与计划离店的客流量。
- **在住统计**：当前酒店内实际在住的客人数量/房间数量。
- **实时出租率**：反映当日酒店客房的利用效率。
- **剩余可售**：今日仍可对外售卖的房间总量。

### 3.2 7天库存日历
提供直观的色块日历，展示包含今日在内的未来一周库存状态：
- **充足 (绿色)**：可用库存大于 2 间。
- **紧张 (黄色)**：可用库存介于 1 至 2 间。
- **售售 (红色)**：可用库存为 0 间。

### 3.3 快捷运营入口
提供快速跳转至房控日历、订单管理、价格查询、房态管理等高频操作模块的通道。

### 3.4 智能流速监测 (Pacing Analysis)
系统需实时监测未来 7 天的库存消耗情况，并给出经营建议：
- **消耗速度计算**：对比昨日此时与当前时刻的 Pickup（净增预订）与可用库存的比例。
- **状态等级**：
  - **太快 (Critical)**：库存余量低且昨日流入量大，需立即提价。
  - **快 (Fast)**：流入量显著。
  - **正常 (Normal)**：符合季节性预期。
  - **偏慢 (Slow)**：流入量低于平均水平，需考虑促销。
  - **非常慢 (Dead)**：几乎无流入，需紧急降价或渠道投放。

### 3.5 渠道全量价值矩阵
不仅展示订单量，需聚合展示：
- **预订量 (Quantity)**：各渠道产生的订单总数。
- **预订金额 (GMV)**：各渠道贡献的总流水。
- **平均房价 (ADR)**：该渠道的平均客单价（GMV / 订单量）。

### 3.6 经营趋势双轴图
在同一时间轴（7天/30天）展示：
- **出租率 (OCC)**：曲线图，反映利用率。
- **平均价格 (ADR)**：柱状图或曲线图，反映价格策略效果。
- **目标**：观察价格变动对出租率的敏感度（价格弹性）。

### 3.7 异常订单预警中心
系统自动识别并汇总待处理的异常订单：
- **超卖风险**：库存为负的订单。
- **价格异常**：成交价显著低于成本价或基础价。
- **未确认订单**：渠道下单后 CRS 超过 5 分钟未自动确认的订单。
- **重复订单**：同一入住人、同一日期的多笔重合预订。

---

## 四、 权限与隔离规则
- **租户隔离**：所有数据展示必须严格限制在当前用户所属的租户范围内。
- **超管规则**：系统超级管理员在未切换至具体租户前，默认不展示具体指标，需引导用户先选定租户。

# 第二部分：技术设计 (Technical Design)

## 一、 数据模型与字段映射

### 1.1 核心指标统计逻辑
| 业务指标 | 对应表名 | 技术实现逻辑 (SQL/Field) |
|------|---------|---------|
| 今日新订单 | `reservation` | `count(*)` WHERE `tenant_id = ?` AND `created_at >= CURDATE()` |
| 今日入住 | `reservation` | `count(*)` WHERE `tenant_id = ?` AND `check_in_date = CURDATE()` AND `status != 'cancelled'` |
| 本月收入 | `reservation` | `sum(total_price)` WHERE `tenant_id = ?` AND `created_at >= DATE_FORMAT(NOW(), '%Y-%m-01')` AND `status != 'cancelled'` |
| 活跃酒店数 | `hotel` | `count(*)` WHERE `tenant_id = ?` AND `status = 'active'` |
| 待处理事项 | `reservation` | `count(*)` WHERE `tenant_id = ?` AND `is_manual = true` AND `status = 'active'` |
| 在住统计 | `reservation` | `count(*)` WHERE `tenant_id = ?` AND `check_in_date <= today` AND `check_out_date > today` AND `status = 'active'` |

### 1.2 库存与聚合逻辑
- **实时可用库存**：
  - 数据来源：`inventory` 表。
  - 聚合字段：`available_rooms`。
  - 过滤条件：`hotel_id` (或 `hotel_code` 关联), `date`, `tenant_id`。
- **出租率计算**：
  - 公式：`(InHouseReservations / hotel.total_rooms) * 100`。

## 三、 系统集成细节

### 3.1 租户上下文解析
后端通过 `DashboardController.getTenantId(HttpServletRequest)` 获取租户 ID：
1. 优先从 `X-Tenant-Id` 请求头解析。
2. 若请求头不存在，则调用 `jwtUtil.extractTenantId(token)` 从令牌中提取。
3. 若均无法获取，返回 `400 Bad Request` 提示需选择租户。

### 3.2 路由集成实现
`src/pages/Dashboard.jsx` 实现逻辑：
```javascript
const Dashboard = () => {
  const { selectedHotel } = useHotelContext();
  return selectedHotel ? <HotelDashboard /> : <GroupDashboard />;
};
```
